# Career Quest implementation

**Status:** playable end to end · verified 2026-11-14
**Architecture:** `docs/CAREER_QUEST_ARCHITECTURE.md`
**Catalog:** `software-engineer-1.0` · **Rubric:** `career-quest-rubric-1.0`

## What is implemented

### Game flow

1. **Dashboard / start screen** — Career Quest title, introduction, player level, XP, completed
   missions, achievements, mission history, **Continue game** and **Start new game**.
2. **Career and difficulty selection** — Software Engineer is playable. AI Engineer, Data Scientist,
   Cybersecurity Analyst, Product Manager, and Business Analyst are listed as future careers and
   cannot start an unsupported run. Beginner, Intermediate, and Advanced select different hidden
   test sets and XP multipliers.
3. **Introduction cinematic** — a three-step animated onboarding sequence: offer letter and company
   branding, manager and team introductions, then the first-day briefing with the current
   objectives. It is server-state gated (first mission, no player actions yet) and dismissible.
4. **Virtual workplace** — mission board, deadline timer, progress tracker, task/objective panel,
   manager chat, team desk, notifications/activity feed, live status updates over SSE, and a
   resumable run URL at `/career-quest/run/{run_id}`.
5. **AI manager** — local Ollama only. The manager introduces missions, answers player questions,
   gives grounded hints, reacts to decisions, and delivers authored changing requirements. Recent
   mission dialogue is included in the prompt so replies have mission/session context. Every reply
   is labeled `Local AI` or `Scenario` in the UI.
6. **Missions and final boss** — four connected missions:
   - Debug the billing API (debugging + edge cases)
   - Implement skill ranking (feature implementation + deterministic ties)
   - Handle a checkout incident (incident response + communication)
   - Final challenge: release readiness (debugging, coding, risk prioritization, communication)
   Each has a story brief, objectives, difficulty-aware tests, decisions, manager dialogue, a
   changing-requirement event, a written debrief, evaluation, XP, and completion status.
7. **Coding workspace** — Monaco editor, starter code, public examples, hidden server-side tests,
   submission polling, pass/fail feedback, isolated execution status, and mission completion.
8. **Decisions and consequences** — multi-select authored actions scored against a per-mission
   rubric, plus a written debrief evaluated for problem-solving and communication. Changing
   requirements arrive after the first decision and alter the edge cases the hidden tests cover.
9. **Progression** — append-only XP ledger, level curve, mission unlocking, achievements
   (`first_mission`, `clean_execution`, `incident_responder`, `boss_cleared`,
   `career_quest_complete`), per-skill evidence, persistent SQLite state, and resume after reload.
10. **Final report** — actual test execution evidence, five dimensions, overall practice score,
    career-readiness band, mission completion, demonstrated/weak skills, recommended practice, and
    a roadmap generated by the existing SkillBridge `generate_roadmap` learning system with course
    links. A report link opens the existing `/learn` workspace.

### Backend and data

- FastAPI router at `/api/v1/career-quests/*`, all player endpoints behind `Depends(current_user)`.
- Server-owned state machine and scoring; clients cannot submit user IDs, scores, XP, unlocks, or
  achievement state (`extra="forbid"` request models).
- SQLite tables: `career_quest_runs`, `career_quest_missions`, `career_quest_interactions`,
  `career_quest_attempts`, `career_quest_skill_evidence`, `career_quest_xp_events`,
  `career_quest_achievement_awards`.
- Idempotent attempts and XP events, ownership checks on every run/mission/attempt/report lookup,
  bounded source size, attempt limits, and a runner concurrency guard.
- SSE topics: `career_quest.run`, `career_quest.mission`, `career_quest.attempt`,
  `career_quest.progression`, `career_quest.report`.

### AI routing

| Task | Model | Behavior |
| --- | --- | --- |
| Manager dialogue | `qwen2.5:7b` | 20s timeout; falls back to `gemma2:2b`, then authored scenario text. |
| Reflection evaluation | `qwen2.5-coder:3b` | Strict JSON schema; deterministic rubric if unavailable. |
| Lightweight fallback | `gemma2:2b` | Bounded manager wording only. |
| Skill similarity | all-MiniLM-L6-v2 | Supporting evidence only; never determines completion. |

Generations are serialized with a lock, unavailable models are checked against installed Ollama
tags, JSON is schema-validated, and `keep_alive=0` unloads each model after use. Player text is
treated as data, not instructions. On a 7 GB machine the 7B manager may exceed the 20s timeout; the
Gemma fallback and authored text keep the game responsive.

## Isolated code execution

`backend/runner/service.py` is a separate Judge0-compatible service. It executes each submission in
a fresh Docker container with:

- no network
- read-only container root
- read-only mount of the temporary source directory only
- unprivileged user and `no-new-privileges`
- 128 MB memory, 0.5 CPU, 64 processes, 8 second wall-clock timeout

FastAPI never uses `eval`, `exec`, or a local subprocess to run player code. Expected outputs stay in
`career_quest_catalog.py` and are compared in the backend service.

Start it with:

```bash
npm run career-quest:runner
# or: python3 backend/runner/service.py
```

Health check: `curl http://127.0.0.1:2358/health`

## Configuration

`backend/.env` for local development:

```dotenv
OLLAMA_BASE_URL=http://127.0.0.1:11434
CAREER_QUEST_MANAGER_MODEL=qwen2.5:7b
CAREER_QUEST_CODER_MODEL=qwen2.5-coder:3b
CAREER_QUEST_FALLBACK_MODEL=gemma2:2b
CAREER_QUEST_MODEL_TIMEOUT_SECONDS=20

CAREER_QUEST_RUNNER_URL=http://127.0.0.1:2358
CAREER_QUEST_RUNNER_TIMEOUT_SECONDS=20
# CAREER_QUEST_RUNNER_TOKEN=share-with-runner-process
# CAREER_QUEST_RUNNER_LANGUAGE_ID=71
```

`CAREER_QUEST_RUNNER_URL` is intentionally empty by default in `config.py`; the local `.env` points
it at the runner above. Without a runner, coding attempts are marked `UNAVAILABLE` and no technical
score or XP is awarded.

## How to run the game

```bash
# 1. Local AI (already installed models)
ollama serve

# 2. Isolated code runner (Docker must be running)
npm run career-quest:runner

# 3. FastAPI
npm run fastapi:dev

# 4. Next.js
npm run dev
```

Open `http://localhost:3000`, create/sign in to a candidate account, then open
`http://localhost:3000/career-quest`.

The Docker image used by the runner is `python:3.12-slim`. Pull it once if needed:

```bash
docker pull python:3.12-slim
```

## What remains incomplete or intentionally limited

- The report's SkillBridge roadmap is generated with the existing roadmap generator and linked to
  `/learn`, but it is not auto-saved over a user's existing learning roadmap. Adopting it is an
  explicit product decision.
- The manager uses the last six stored interactions as memory within the current mission. It does not
  summarize the entire run into a long-term memory store.
- The repository-wide lint failure is pre-existing (mostly `src/lib/workspace-provider.tsx` and other
  components); Career Quest files lint clean.
- The local runner is single-process and in-memory, intended for local/hackathon use. A deployment
  needs a durable job store, authentication token, and a multi-user execution service.
- No paid AI or code-execution API is used.
